## 1. Идеи решений и выбор структур данных

### Общие принципы

- **Массив `int[]` — основная структура.** Доступ по индексу за O(1), никаких накладных расходов;
  этого достаточно почти для всех задач. Коллекции (`ArrayList`, `HashMap`) используются только там,
  где без них не обойтись.
- **Массив не хранится, если он не нужен для ответа** (задачи 1, 7, 25–27, 32, 34, 36, 49–52, 54):
  числа обрабатываются сразу при чтении, память O(1) или O(размер ответа).
- **Переполнение.** Суммы — в `long` (n · 2^31 < 2^48). Где не хватает и `long`
  (сумма квадратов, скалярное произведение, сумма произведений пар — до 2^79…2^94), итог
  накапливается в `BigInteger`; длина чисел ограничена, поэтому операция по-прежнему O(1).
- **Проверка ввода** во всех задачах: нечисловой ввод, длина/размер вне допустимых границ,
  нарушение условий задачи (k = 0, неотсортированный массив, нули там, где их быть не должно,
  некорректный запрос и т. п.). При ошибке печатается сообщение и частичный ответ не выводится.

### Базовые операции (1, 5–7, 9, 11, 25–28, 30–32, 36)

Один или два линейных прохода. Минимум/максимум и второй максимум (1, 7) — без хранения массива.
Среднее (6, 11, 30) требует двух проходов, поэтому массив сохраняется. Медиана (28) — через сортировку.
Дисперсия (30) считается через отклонения от среднего, а не формулой Σx²/n − x̄²: так нет потери
точности при больших близких числах. Произведение (26) — по модулю 10^9 + 7 после каждого умножения,
с приведением отрицательных остатков к [0, MOD).

### Сортировки (13–24)

- **Вручную, как требует условие:** выбором (13), вставками (14), пузырьком с досрочным выходом
  и подсчётом обменов (15), подсчётом (20).
- **Сортировка подсчётом** использована и там, где ключ лежит в малом диапазоне: сумма цифр 0..90 (17),
  частота 1..n (22). Она устойчива, что прямо нужно в 17 и 22.
- **Кодирование ключа** (16): число x заменяется на 2·|x| + (x ≥ 0 ? 1 : 0) в `long`, после чего
  обычная сортировка даёт порядок «по модулю, при равенстве — отрицательный первым».
- **Слияние двух отсортированных массивов** (19) — два указателя, O(n + m).
- В остальных задачах (18, 21, 23, 24) используется `Arrays.sort`, так как ручная реализация
  условием не требуется.

### Поиск и подсчёт (2–4, 8, 10, 12, 29, 33–35)

Линейный поиск с ранним выходом там, где это возможно (2, 9). `ArrayList` (8) — потому что заранее
неизвестно, сколько будет положительных и отрицательных. Мода (29) — сортировка и подсчёт длин серий;
строгое сравнение длины серии автоматически даёт наименьшее значение при равных частотах.

### Преобразования массивов (37–47)

Все задачи с требованием «на месте» решены двумя указателями без дополнительных массивов:
разворот (37), удаление дубликатов (40), удаление элемента (41), перенос нулей (43).
Вставка в отсортированный массив (42) — позиция ищется бинарным поиском за O(log n),
затем сдвиг хвоста. Сжатие диапазона (46) — сортировка копии, удаление повторов и бинарный поиск
ранга. Чередование знаков (44) — через два вспомогательных массива: стабильная перестановка
на месте потребовала бы O(n²). Поворот на 90° (47) печатается сразу по формуле `a[n−1−j][i]`,
без второй матрицы.

### Матрицы (48–60)

Суммы, минимумы и максимумы строк/столбцов (49–52) и сумма главной диагонали (54) считаются
при чтении, матрица не хранится. Транспонирование (48) — на месте, обменом пар над диагональю.
Умножение (56) — по определению, O(n·m·k). Спираль (57) — четыре сдвигающиеся границы.
Определитель 3×3 (59) — разложение по первой строке, O(1).

### Нетривиальные задачи

| № | Задача | Решение и почему так |
|---|---|---|
| 12 | Пара с заданной суммой | Перебор пар — O(n²), до 5·10^9 операций. Проход **справа налево** с `HashMap<число, ближайший индекс справа>`: для a[i] ищется s − a[i]. Каждая новая найденная пара имеет меньший i, поэтому в конце остаётся пара с наименьшим i, а при нём — с наименьшим j. Элемент кладётся в таблицу после поиска, чтобы не образовать пару с самим собой. O(n) в среднем. |
| 33 | Количество инверсий | Модификация сортировки слиянием. При слиянии, когда берётся элемент из правой половины, он меньше всех оставшихся элементов левой — это сразу m − i + 1 инверсий, без перебора. Равные элементы не считаются (сравнение `<=` при выборе левого). Счётчик в `long`: до ~5·10^9. O(n log n). |
| 34 | Максимальная сумма подмассива | Алгоритм Кадане: `cur = max(a[i], cur + a[i])`, ответ — максимум `cur`. Инициализация первым элементом, а не нулём, — иначе для массива из одних отрицательных ответ был бы 0 вместо наибольшего элемента. O(n), O(1) памяти. |
| 35 | Префиксные суммы | Массив `p` длины n + 1, `p[0] = 0`, сумма на [l, r] = `p[r+1] − p[l]` — одно вычитание. Лишний нулевой элемент убирает частный случай l = 0. O(n) предпосчёт + O(1) на запрос. |
| 38 | Циклический сдвиг влево | Тройной разворот: развернуть первые k, остальные, затем весь массив ([A B] → [A′ B′] → [B A]). k заменяется на k mod n, поэтому допустимо k > n. O(n), O(1) доп. памяти. |
| 45 | Разбиение по опорному | Трёхчастное разбиение Дейкстры («голландский флаг»): указатели lt, i, gt и инвариант `< p | = p | не просмотрено | > p`. После обмена с gt указатель i не сдвигается — пришедший элемент ещё не проверен. O(n), O(1) доп. памяти. |
| 53 | Седловые точки | Сначала массивы `rowMin` (n) и `colMax` (m), затем каждый элемент проверяется за O(1). Без них проверка каждого элемента стоила бы O(n + m), всего O(n·m·(n + m)). Сравнение на равенство находит и все точки при одинаковых значениях. O(n·m). |
| 60 | Острова из единиц | Обход в ширину (BFS) с очередью на массивах и матрицей отметок. Рекурсивный DFS не выбран: на острове до 10^6 клеток рекурсия переполнила бы стек. Каждая клетка попадает в очередь не больше одного раза. O(n·m). |

Требование «не менее 80 %» выполнено. Почти все непокрытые строки — по одной на класс: это строка
объявления класса, где JaCoCo учитывает неявный конструктор по умолчанию. Тесты вызывают только
статический `main`, объект класса не создаётся, поэтому эта строка не выполняется.

Каждый тест запускает `main` с подставленным вводом через `System.setIn` и проверяет напечатанный
вывод — то есть тестируется программа целиком, как её видит пользователь. В каждой задаче покрыты:

- **обычные случаи** — пример из условия и типичные входные данные;
- **граничные случаи** — минимальная длина, все элементы равны, уже отсортированный и обратный
  массив, отсутствие ответа, одна строка/столбец матрицы;
- **отрицательные числа и крайние значения** `Integer.MIN_VALUE`, `Integer.MAX_VALUE`;
- **переполнение** — входы, на которых результат не помещается в `int` (а где нужно — и в `long`);
- **все ошибки ввода** — нечисловые данные, длина/размер вне границ, нехватка элементов,
  нарушение условий задачи.
