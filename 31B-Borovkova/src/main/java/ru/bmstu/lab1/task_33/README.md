# Задача 33. Количество инверсий

Идея: модификация сортировки слиянием. Метод mergeSort(a, t, l, r) сортирует
отрезок a[l..r] и возвращает число инверсий в нём. Каждая инверсия (i, j)
относится ровно к одному из трёх видов:
1. оба индекса в левой половине — их считает рекурсивный вызов для левой половины;
2. оба в правой половине — рекурсивный вызов для правой;
3. i в левой, j в правой — их считаем при слиянии.

При слиянии обе половины уже отсортированы. Если берётся элемент из правой
половины a[j] (он строго меньше a[i]), то он меньше и всех оставшихся элементов
левой половины a[i..m] — это ровно m − i + 1 инверсий, они прибавляются за O(1).
При равенстве (a[i] <= a[j]) сначала берётся левый элемент, поэтому равные
элементы инверсией не считаются (по условию нужно a_i > a_j, строго).

Количество инверсий может достигать n(n − 1) / 2 ≈ 5·10^9 (массив по убыванию),
это больше предела int, поэтому счётчик — long.
Вспомогательный массив t создаётся один раз и передаётся во все вызовы.

Время: O(n log n) — log n уровней рекурсии, на каждом уровне слияние суммарно O(n),
подсчёт инверсий не добавляет лишних проходов.
Память: O(n) — массив и вспомогательный массив t; плюс O(log n) на стек рекурсии.
